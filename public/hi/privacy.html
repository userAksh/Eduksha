Privacy Policy

नोट: यह हिंदी अनुवाद आपकी सुविधा के लिए है। किसी भी मतभेद की स्थिति में अंग्रेज़ी संस्करण आधिकारिक माना जाएगा।

यह Privacy Policy साफ़ तरीक़े से बताती है कि जब आप (parent) और आपका बच्चा Eduksha का mobile ऐप या यह website ("Service") use करते हैं, तब Eduksha ("हम") कौन-सी जानकारी लेता है, उसका क्या करता है, किसके साथ शेयर करता है, और आपके पास क्या options हैं।

Eduksha भारत से एक personal venture के तौर पर चलाया जाता है। ये ऐप माता-पिता के लिए बना है, ताकि वो अपने बच्चों के लिए — मुख्यतः 8 से 13 साल के बच्चों के लिए — इसे use करें। Account हमेशा parent का होता है। बच्चा एक ऐसी profile use करता है जिसे parent ही manage करते हैं।

1. यह Policy किस पर लागू होती है

ऐप में दो रोल हैं:

  • Parent — फ़ोन number से sign up करते हैं, बच्चे की profile बनाते हैं, और बच्चे का काम review करते हैं।
  • बच्चा — parent द्वारा बनाई गई profile use करता है। बच्चा अपना account ख़ुद नहीं बनाता, और न ही ईमेल या social-media से login करता है।

चूँकि Eduksha का बड़ा हिस्सा 13 साल से कम उम्र के बच्चों के लिए है, हम बच्चे की profile से जुड़ा सारा data भारत के Digital Personal Data Protection Act, 2023 (DPDPA) के सख़्त नियमों के तहत संभालते हैं — और जहाँ ज़रूरी हो वहाँ अमेरिका के Children's Online Privacy Protection Rule (COPPA) और EU के General Data Protection Regulation (GDPR) के नियम भी लागू होते हैं। पहली बार parent जब sign in करते हैं तभी उनकी consent ली जाती है — और बच्चे की कोई भी profile बनाने से पहले यह consent ज़रूरी है।

2. हम क्या जानकारी लेते हैं

हम सिर्फ़ वही data लेते हैं जो ऐप चलाने के लिए ज़रूरी है। हम न किसी third party से data ख़रीदते हैं, न ad profiles बनाते हैं।

आप (parent) से

  • आपका फ़ोन number (Firebase Authentication से OTP-based sign-in के लिए)।
  • Display name और avatar emoji, अगर आप दें तो।
  • Push notification token (Firebase Cloud Messaging) — ताकि pending review की notification भेज सकें।
  • Google Play Integrity App Check के लिए ज़रूरी device identifiers, ताकि हम confirm कर सकें कि request किसी असली Eduksha install से ही आ रही है।

बच्चे के बारे में

  • बच्चे का पहला नाम (या nickname)।
  • Class और board (जैसे CBSE)।
  • Gender (सिर्फ़ default avatar चुनने के लिए — किसी third party या किसी और user से कभी share नहीं होता)।
  • Date of birth — optional, अगर आप दें तो।
  • 4 अंकों का PIN जो आप बच्चे के device के लिए set करते हैं (hashed करके save होता है, plain में नहीं)।
  • Push notification token, अगर बच्चा paired device पर है।

ऐप के अंदर बनी activity

  • बच्चे द्वारा upload की गई homework, notes, या worksheet की photos।
  • MCQ में चुने गए answers और last-attempt का score।
  • लिखे हुए जवाब का text और AI से लौटाया गया feedback।
  • आपके दिए हुए tasks, बच्चे का submission, और आपकी review note।
  • Streak और milestone counters।
  • Friend connections की एक छोटी list (parent ID, child ID, नाम, class) — यह तभी बनती है जब एक parent referral link share करते हैं और दूसरे parent अपने बच्चे के लिए उसे claim करते हैं।

Device और network से

  • लगभग का IP address (जब ऐप हमारे server से बात करता है तो Google Cloud इसे automatically लेता है — security और abuse रोकने के लिए)।
  • Crash और stability logs, अगर आपने Google Play crash reporting के लिए opt-in किया हो।
  • Google Play का install-referrer code — पहली बार ऐप खुलने पर सिर्फ़ एक बार use होता है, deferred deep-link friend invites के लिए।

हम नहीं लेते: आपकी exact location, contacts, microphone audio, camera video (camera permission सिर्फ़ उन homework photos के लिए है जिन्हें बच्चा ख़ुद submit करता है), ऐप के बाहर का browsing history, या कोई social-media data।

Website (eduksha.in) पर visit करने वालों से

ऐप से अलग, हमारी marketing website eduksha.in पर हर visit पर दो privacy-respecting analytics tools load होते हैं। दोनों में से कोई भी आपका name, email या phone number जैसी personal information collect नहीं करता। हम इन्हें सिर्फ़ ये समझने के लिए use करते हैं कि कौन से marketing efforts काम कर रहे हैं और कहाँ usability issues हैं:

  • Microsoft Clarity (Microsoft Corporation) — anonymised session recordings (mouse, scroll, click) और aggregated heatmaps। Form fields (waitlist form सहित) by default masked रहते हैं — आप जो type करते हैं वो कभी record नहीं होता। UX issues पकड़ने के लिए।
  • Meta Pixel (Meta Platforms Inc.) — anonymous page-view और conversion events (जैसे waitlist signup), Facebook/Instagram पर हम जो ads चलाते हैं उनकी performance measure करने के लिए। Pixel सिर्फ़ ये देखता है कि कोई page या event हुआ — आपने form में क्या भरा वो नहीं देखता। सिर्फ़ marketing measurement के लिए, बच्चों की behavioural profiling कभी नहीं।

आप कभी भी standard browser tracker-blocker (जैसे Brave shields, uBlock Origin, या browser की "Block third-party cookies" setting) से इन्हें block कर सकते हैं। team@eduksha.in पर लिखें — हम Clarity recordings से आपकी visits exclude कर देंगे।

4. किसके साथ data share होता है

सिर्फ़ उन्हीं third parties के साथ जो ऐप चलाने के लिए ज़रूरी हैं:

  • Google LLC / Firebase — authentication, Firestore database, photos के लिए Cloud Storage, Cloud Functions, Cloud Messaging, App Check, Crashlytics (अगर enabled हो)। Google हमारे data processor के रूप में काम करता है।
  • Google Gemini API — quiz या feedback बनाते वक़्त बच्चे की homework photo या लिखा हुआ जवाब Gemini तक जाता है। Prompt में हम बच्चे का नाम या कोई PII (personal info) नहीं भेजते — सिर्फ़ academic content। Google की API terms के मुताबिक़, prompts और outputs को Google के general-purpose models train करने के लिए use नहीं किया जाता।
  • Google Play / Android — install-referrer और notification delivery का infrastructure।
  • Microsoft Clarity (सिर्फ़ website पर) — anonymised session recordings और heatmaps, UX research के लिए। Form fields by default mask रहते हैं।
  • Meta Pixel (सिर्फ़ website पर) — anonymous page-view और conversion events, Facebook/Instagram ads की effectiveness measure करने के लिए।

इनके अलावा हम किसी और third party के साथ कुछ share नहीं करते। हम personal data न बेचते हैं, न किराये पर देते, न उसका लेन-देन करते हैं।

5. Data कहाँ रखा जाता है

आपका data Google Cloud पर रखा जाता है (regions Google manage करता है — भारतीय users के लिए मुख्यतः Mumbai)। Photos Cloud Storage में, और profile व activity records Firestore में रहते हैं। Default रूप से Google का encryption-at-rest और TLS-in-transit लागू है।

6. हम data कितने वक़्त तक रखते हैं

जब तक आपका account active है, तब तक data रखते हैं। अगर आप account, बच्चे की profile, या किसी ख़ास upload को delete करते हैं, तो 30 दिन के अंदर मूल records और photos मिटा दिए जाते हैं। Backup copies Google Cloud की normal प्रक्रिया से और 90 दिन में पूरी तरह साफ़ हो जाती हैं। पूरे steps Account delete करें पर देखिए।

7. आपके अधिकार

DPDPA, GDPR और इसी तरह के क़ानूनों के तहत आप यह कर सकते हैं:

  • अपने और बच्चे के data तक access लेना।
  • ग़लत जानकारी को ऐप के अंदर से या ईमेल भेजकर ठीक करना।
  • अपना account और बच्चे का सारा data delete करना — यहाँ देखें।
  • किसी ख़ास processing पर आपत्ति करना।
  • कभी भी अपनी consent वापस लेना। ध्यान रहे, consent वापस लेने पर उस बच्चे की profile के लिए ऐप काम करना बंद कर देगा।
  • भारत के Data Protection Board या अपने local authority के पास शिकायत दर्ज करना।

इनमें से कोई भी अधिकार use करने के लिए team@eduksha.in पर ईमेल भेजिए। हम 30 दिन के अंदर जवाब देते हैं।

8. बच्चों की privacy

Eduksha बच्चों के लिए बना है, और यह बात हम हल्के में नहीं लेते:

  • कोई भी बच्चा parent के verified phone-OTP session के बिना अपनी profile नहीं बना सकता — पूरी फ़ुलस्टॉप।
  • News और AI से बना content एक सख़्त kid-safety prompt से होकर आता है, जो हिंसा, राजनीति, धर्म, और डराने वाली कोई भी चीज़ हटा देता है।
  • ऐप में कोई ads नहीं, कोई behavioural tracking नहीं, अजनबियों से कोई chat नहीं, और बच्चों को target करने वाली कोई in-app purchase नहीं।
  • Friend connections सिर्फ़ उन्हीं बच्चों के बीच होते हैं जिनके parents ने जानबूझकर एक referral link share और claim किया है। बच्चा किसी और user को न search कर सकता है, न contact।
  • अगर हमें कभी पता चले कि किसी बच्चे ने parent की consent के बिना sign up किया है, तो हम उससे जुड़ा सारा data और parent record तुरंत delete कर देते हैं।

9. Security

हम Google Cloud के enterprise security stack पर depend हैं: transit में TLS, rest पर AES-256 encryption, और Firestore security rules जो हर parent / बच्चे को सिर्फ़ अपने subtree तक सीमित रखती हैं। Cloud Functions को App Check protect करता है। फिर भी, कोई भी system 100% safe नहीं होता — इसलिए हमारी आपसे request है कि अपने device पर एक मज़बूत password / lock रखें, और OTP या PIN किसी को न दें — किसी को भी नहीं।
